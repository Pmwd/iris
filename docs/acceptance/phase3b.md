# Phase 3B 受控 Scholar 编排原型

> 日期：2026-10-25  
> 状态：编排原型与重试/退避已实现；两轮研究草稿均已由用户接受；两轮 Scholar 任务均已完成。
> 边界：不自建网页搜索/抓取；使用原生 WebSearch/WebFetch；Iris 只做编排。

## 1. 已实现

- Scholar 角色；Task 支持 `role=scholar`。
- `research` 工具档位：`Read,Glob,Grep,WebSearch,WebFetch`，不含 Write/Edit。
- 研究计划生成：
  - 自动生成 3–5 个问题；
  - 计划可编辑；
  - 用户确认后才开始。
- 研究任务：
  - 每个子问题独立 CLI session；
  - 窄上下文，不共享父 transcript；
  - 并发上限 2；
  - 单子任务最大 8 轮、600 秒；
  - 可取消；重启标记中断；
  - 结果、来源和状态持久化。
- 汇总：
  - 生成结构化研究 note 草稿；
  - 区分 Known facts / Opinions / Hypotheses / Sources / Gaps；
  - 只有用户接受后才进入上下文。
- 前端 Scholar 面板：生成计划、编辑问题、开始、查看子任务/来源、取消、审查草稿。
- Testing 从新建任务 UI 中移除；已有 Testing 代码/数据保留。
- Schema v6；35 个后端测试通过，前端构建通过。
- 子任务重试：默认 3 次尝试（2 次重试），指数退避 2s / 4s；记录每次尝试。
- 失败详情记录 terminal reason、HTTP 状态和 CLI result。
- 首轮真实任务之前已发生的泛化错误无法回填；新任务会记录完整原因。

## 2. 第一个真实研究任务

主题：个人知识管理中如何区分事实、观点和待验证假设。

- 自动生成 5 个子问题；
- 并发 2；
- 结果：**2 个子任务成功，3 个失败**；
- 成功的子任务带大量来源 URL；
- 失败错误被记录为通用 `CLI returned an error`（见下一节改进）；
- 汇总生成了约 12.9k 字符的研究草稿，明确说明 3 个子问题失败、相应结论只能作为假设，并包含来源、事实、观点、假设和 gaps；
- 草稿仍是 `draft`，**没有自动接受**。

这说明编排闭环成立，但 Web 子任务的可靠性还不足，不能把“任务完成”误认为“5 个子问题都验证成功”。

## 3. 发现的问题

1. **并发 Web 子任务失败率较高。** 2 个并发下仍有 3/5 失败；可能是 API/Web 工具限流、超时或返回错误。需要在第二次真实任务前补错误详情并考虑重试/退避或默认并发 1。
2. **错误信息此前过于笼统。** 已改为记录 `terminal_reason`、HTTP 状态和 CLI result，但本任务已经运行完，无法回填。
3. **部分任务完成不等于全部证据充分。** 汇总草稿正确标出了失败子问题和未验证假设，这点符合设计。
4. **成本/耗时尚未按子任务持久化。** 无法从数据库直接汇总每个子任务的成本与时长。
5. **第二轮知识复用尚未验证。** 需要先接受第一轮研究草稿，才能测试后续任务是否真正复用。
6. **Scholar UI 已构建，但尚未用浏览器完整走一遍计划→运行→审查。**

## 4. 第二轮复用任务

- Task：`设计可执行的研究笔记模板与复核流程`（`fa7e316a-c851-4e01-bb0d-6408ef4d7134`）
- Source task：第一轮研究任务
- 第一轮研究 note 已由用户确认并接受
- 上下文预览：第一轮 note 以 `reason=handoff` 注入
- Web：关闭；不进行新的网页检索
- 计划：5 个子问题

  - 主张类型/证据状态/来源谱系/反证条件/复核流程
  - 明确说明本轮没有新的网页检索，事实来自给定 findings
  - 继承第一轮的来源编号与证据边界
- 草稿已由用户接受，任务标记完成

复用证据：

- 第一轮 note 以 handoff 注入，而不是靠关键词碰巧命中；
- 第二轮没有重新做网页检索，子任务来源来自第一轮研究；
- 汇总内容继承第一轮的来源、事实/观点/假设边界，并扩展为模板和复核流程。

## 5. 下一步

1. 两轮研究草稿均已接受，Scholar 两轮验证完成。
2. 下一步定义 Mentor v0 的 goal/capability/blind_spot/progress 模型。
3. 如需更多真实任务，优先使用本地研究（web 关闭）验证复用，再逐步恢复 Web 并观察重试成功率。
4. 不提前实现 Obsidian 或多 Agent。

## 6. 已知限制与结论

- 第一轮 Web 研究仍有 3/5 子任务失败；重试/退避已实现，但第二轮没有触发重试，真实 Web 成功率仍需新任务验证。
- 第二轮研究草稿 19.7k 字符，上下文 handoff 截断到约 12k 字符；长研究 note 的后续复用可能丢失尾部内容。
- 尚未持久化每个子任务的成本和耗时，只有整体完成时间。
- Scholar UI 已构建，但本轮验收主要走 API；浏览器完整研究流程仍需手工验证。
- 两轮验证已证明：受控子对话、并发、来源保留、handoff 和知识复用可以工作；但这不等于所有 Web 子任务都可靠，也尚未验证 Mentor。

结论：Scholar 编排作为 Phase 3B 原型成立，可以进入“审查第二轮草稿并决定 Mentor”的阶段。
