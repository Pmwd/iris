# Phase 4 验收：Session 化 + 三层记忆 + 双角色

- 目标：验证真实 CLI 下的 Session 聊天、原始/摘要/事实三层记忆，以及 Coding / Scholar 两个角色。
- 前置：Windows、Python 3.12、Node 20+、Claude Code CLI 已登录；建议使用独立 `IRIS_DATA_DIR`，避免污染现有数据。
- 自动化基线：`pytest backend/tests -q` 通过（31 个测试）；`cd frontend && npm run build` 通过。

## 1. 启动

```powershell
$env:IRIS_DATA_DIR = "D:\vibe\Iris\data-acceptance"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>，确认侧栏显示 Coding / Scholar 两个角色、记忆库与工作区入口。

## 2. 工作区

- [ ] 进入「工作区」→ 新建，路径使用一个临时目录（例如 `D:\vibe\Iris\data-acceptance\ws`）。
- [ ] 配置 brief；如需执行档位，添加 `PowerShell(python *)`。
- [ ] 打开工作区详情，确认安全提示、会话数、最近更新时间。

## 3. Coding 会话与多轮

- [ ] 侧栏 Coding → 新会话，选择工作区。
- [ ] 发送第一轮：例如“阅读 README，说明项目结构和启动方式；不要修改文件。”选择「只读」。
- [ ] 观察：工具卡片流式出现；结束后出现助手最终回答；`原始日志` 链接可打开 JSONL。
- [ ] 发送第二轮：例如“基于上一轮，列出两个可以改进的点。”确认第二轮为 `resume`（聊天页 meta 显示“续聊”）。
- [ ] 停止：在长时间运行时点「停止」，确认状态变为已取消，随后仍可继续发消息。
- [ ] 确认会话标题可由第一条消息自动生成，并在标题栏可编辑。

## 4. 摘要（L2）

- [ ] 点击「结束会话」→ 确认最终摘要排队；右侧记忆面板出现摘要（或先「重新生成」）。
- [ ] 摘要包含：目标、已完成、关键决策、未决问题、产出/文件、失败与教训。
- [ ] 关闭摘要失败路径：在一条消息中包含 `SUMMARY_FAIL` 仅用于 fake CLI 测试；真实 CLI 下可跳过。
- [ ] 打开「压缩并继续」，等待摘要成功后发送新消息，确认聊天页显示“新 CLI 会话”且记忆面板显示摘要已注入。

## 5. 事实提取与审核（L3）

- [ ] 准备 2–3 个有摘要的会话（可重复 Coding/Scholar）。
- [ ] 进入「记忆库」→「提取事实」，选择角色/工作区/最多会话数，开始提取。
- [ ] 确认只生成「候选」，已接受列表仍为空。
- [ ] 逐条审查：接受一条；编辑一条后接受；拒绝一条。
- [ ] 确认来源会话数量、提取依据、置信度可见；`update` 候选接受后旧事实进入「已归档」。
- [ ] 新建会话，输入与事实相关的内容，右侧「本次注入的长期事实」显示该事实；事实使用次数 +1。
- [ ] 输入不相关内容时，事实不会无条件注入（置顶事实仍可能被选中）。

## 6. Scholar 会话

- [ ] 侧栏 Scholar → 新会话（可不选工作区）。
- [ ] 选择「研究/联网」档位，提出一个需要网页检索的问题。
- [ ] 确认回答保留来源 URL，并区分已知事实、观点/解释、未验证假设。
- [ ] 结束会话并生成摘要；将摘要纳入事实提取范围。

## 7. 隔离与安全

- [ ] 旧 `tasks/runs/notes` 数据在新 UI 中不可见；新上下文 manifest 中没有旧 note。
- [ ] 事实/摘要内容以参考数据块注入，未拼入角色 system prompt。
- [ ] 同一 Session 运行中再次发送 → 被拒绝（409）；同一工作区两个 Coding 会话不能同时运行。
- [ ] 两个 Scholar 会话可以同时运行。
- [ ] 重启后端后，之前的活动 Turn 显示为已中断；摘要/提取不会卡在运行中。

## 8. 观察项

- [ ] 真实摘要长度与成本是否可接受；阈值 8 Turn / 24000 字符是否合适。
- [ ] 事实提取的信噪比；是否出现重复、过度概括或把假设写成事实。
- [ ] 事实注入预算 4000 字符是否挤占任务上下文。
- [ ] resume 失败时「压缩并继续」是否足够恢复。

## 9. 回滚

- 旧表在 v7 迁移中保持不变；回滚到旧版本前先停止后端并备份 `data/iris.db`。
- 新数据（sessions/facts/session_logs）可单独删除，不影响旧表。
