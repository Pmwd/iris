# ADR 0002：Phase 2 上下文检索与预算

- 状态：已采用（2026-10-23）
- 依据：`docs/acceptance/phase2.md`

## 背景

Phase 1 的上下文只包含用户手动选择的项目 note。随着 note 数量增加，人工选择不可扩展，也无法跨项目复用个人偏好。

## 决策

1. 使用 SQLite FTS5 做关键词检索，不引入 embedding/向量数据库。
2. FTS5 使用 unicode61 默认分词；中文查询生成 bigram，并过滤停用词、功能字 bigram 和纯数字；英文匹配使用词边界；FTS 无结果时回退 LIKE。
3. 自动注入必须由本地关键词/中文 bigram 实际命中决定；FTS rank 只作为命中后的排序加分。
4. 项目 note 保留在 `notes`；新增独立 `global_notes`，由用户手写/接受，跨项目参与推荐。
5. 推荐排序考虑：置顶加权、相关度、最近更新、使用次数；**置顶不绕过相关性**。
6. 上下文预算默认 16000 chars / 约 4000 tokens；超出预算的 note 不注入并记录原因。
7. 推荐结果作为默认选择，用户可以显式覆盖；显式选择可以包含未自动命中的全局 note。实际注入内容记录在 run manifest。
8. 只有用户接受/手写的 note 参与检索；不对对话做自动记忆提取。
9. 真正注入上下文时递增 note 的使用次数；被预算排除的 note 不计入。
10. 用户可以给 note 添加 aliases/tags；别名进入 FTS 和本地匹配，用于补偿不同措辞。别名不是语义模型，需要用户维护。
11. Schema v3 自动迁移 v1/v2 数据并重建 FTS；迁移前建议备份。

## 后果

- 检索质量受关键词/分词限制，不是语义检索。
- 中文短词和部分分词依赖 LIKE 回退。
- 预算是启发式，不是模型 tokenizer 的精算。
- 推荐权重是固定规则，需要真实使用数据校准。
- 全局 note 是本地单用户数据；尚无权限分级或自动过期。

## 未决问题

- 是否引入更好的中文分词或 trigram。
- 推荐权重是否需要用户反馈机制。
- 预算是否应按模型/任务类型配置。
- 是否需要 note 的自动过期、敏感度或权限分级。
