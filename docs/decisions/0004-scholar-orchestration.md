# ADR 0004：Scholar 编排层与原生网页工具

- 状态：原型已实现；第一个真实任务部分子任务失败，等待可靠性修正和第二轮复用验证
- 日期：2026-10-24（更新于 2026-10-25）
- 关联：`docs/evaluation/paraphrase-recall.md`、`docs/acceptance/phase3a.md`

## 背景

Testing 角色暂时搁置，测试类任务由 Coding 角色复用 Claude 自身能力完成。下一步优先 Scholar，之后 Mentor。

用户明确了一个边界：

- **不自建网页搜索、网页抓取、排序、反爬、JS 渲染或内容提取能力。**
- 网页访问来自 Harness/Claude Code 自带的原生 `WebSearch` / `WebFetch` 工具。
- Iris 负责缺失的那部分：**受控的任务拆分与并行编排**，而不是一个不受控的巨型对话。

## Phase 3B 技术验证结果

已用真实 CLI 做最小验证：

- `--tools "WebSearch,WebFetch"` + `dontAsk` + 对应允许列表可以工作；
- 一次真实 WebSearch + WebFetch 调用完成，耗时约 15.6 秒，成本约 `$0.1225`；
- 两个独立 CLI session 并行执行完成，总耗时约 2.2 秒，session ID 不同、互不干扰；
- 当前环境没有自定义搜索/抓取代码。

这说明“原生网页工具 + Iris 编排多个小会话”在技术上可行。

## 编排设计草案

### 父任务

Scholar 的研究目标仍是一个 Task。它不是一条无限增长的对话，而是：

1. 生成或由用户提供一份受限制的研究计划；
2. 将计划拆成 3–5 个具体问题；
3. 用户可审阅/删改后再执行。

### 子对话

每个子问题对应一个独立的 CLI run：

- 独立 session；
- 只带与该问题相关的上下文，不注入完整父 transcript；
- 默认工具：`Read,Glob,Grep,WebSearch,WebFetch`；不包含 Write/Edit；
- 有最大轮数、超时和成本上限；
- 结果、来源、状态持久化；
- 可单独取消；取消父任务时取消全部。

### 调度

- 并发上限默认 2（可配置）；
- 一个父任务可以有多个运行中的子任务，不再受现有“同一项目只能一个 run”的限制；
- 进度、队列、失败、取消和重启恢复都要落库；
- 失败子任务不阻塞其他子任务，最终汇总时标明缺失部分。

### 汇总

- 所有子结果先作为材料，不直接写入长期知识；
- 一个汇总步骤生成研究 note 草稿，必须区分：
  - 已知事实
  - 个人观点
  - 待验证假设
  - 来源/出处
- 用户审查/编辑后接受，才成为可复用知识。

### 角色与权限

- Scholar 默认使用只读研究 profile，不修改工作区文件；
- WebSearch/WebFetch 需要按任务显式授权；
- 不构建自定义搜索/抓取；不解析网页为内部索引；
- 不让某个子 Agent 自行扩大工具范围或启动不受控的子 Agent。

## 建议默认值

| 项 | 建议 |
|---|---|
| 子问题数量 | 3–5 个 |
| 并发上限 | 2 |
| 单个子任务最大轮数 | 8 |
| 单个子任务超时 | 10 分钟 |
| 网页工具 | 按任务显式开启 |
| 计划 | 自动生成，但执行前需要用户确认/可编辑 |
| 汇总 | 单独生成结构化研究 note 草稿，用户接受后沉淀 |

## 仍未决定

- 是否允许同一个 Scholar 任务中用户手动增加子问题。
- 子结果是否需要先“接受”再参与汇总，还是汇总只看原始子结果。
- 来源去重/排序的轻量规则；不做自建搜索引擎，但需要基本的来源列表。
- Scholar v0 是否先接本地工作区，网页搜索作为显式可选；建议先本地 + 显式网页。
- Mentor 是否复用同一编排层做“目标拆解”，还是保持单对话。

## 明确不做

- 自建搜索/爬虫/网页渲染/内容抽取。
- 一个不受控的巨型 Agent 会话。
- 自动把网络内容当事实写入长期记忆。
- 多 Agent 自由协作。
- 在 Scholar 验证前实现 Mentor、Obsidian 或阅读器。

## 后续

Mentor v0 没有复用 Scholar 的多子对话编排；它保持单对话，并以用户接受的 typed global note 作为长期状态。见 `docs/decisions/0005-mentor-v0.md`。
