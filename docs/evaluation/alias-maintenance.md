# 高价值 Note 别名维护试点

> 日期：2026-10-24  
> 原则：只为高价值、反复出现的 note 增加别名；不改检索架构，不引入 embedding。  
> 目标：记录漏召回、误召回、维护耗时，判断是否值得继续投入。

## 1. 高价值标准

本次采用的临时标准：

- 是稳定全局偏好，或已被多个跟进任务使用；
- 在真实任务中确实被注入过；
- 预期未来还会被类似任务复用。

本次选择：

| Note | 理由 | 别名 |
|---|---|---|
| 水果偏好（示例） | 多个水果任务反复使用 | 安全、身体不适、饮食禁忌、聚会、野餐、采购 |
| 两人份水果清单 outcome | 被聚会、预算、野餐任务复用 | 采购清单、两人份、预算、聚会、野餐 |
| 健身偏好 | 稳定的全局偏好 | 复合动作、杠铃、力量训练、全身训练 |

未选择：

- 阅读偏好：目前使用次数和复用频率不够高，暂不维护别名。
- CSV export outcome / Category filtering outcome：coding 场景，当前不是生活任务重点。
- 水果采购清单 outcome：与两人份清单高度重叠，暂不重复维护。

## 2. 维护耗时

- 通过 API 更新 3 条 note 的别名：**0.179 秒**。
- 人工挑选/决定别名：本轮约 **2–3 分钟**（粗略计时，非精确基准）。
- 维护成本主要不是写入，而是**预判未来会怎么改写**；note 越多，这个成本越难控制。

## 3. 只读检查结果

创建临时任务，仅检查 context preview，然后删除任务；没有运行 CLI，没有接受结果。

| 检查任务 | 选中 note | 漏召回 | 误召回/噪声 | 判断 |
|---|---|---|---|---|
| 聚会准备安全食物 | 水果偏好、两份水果清单 | 无 | 两份清单都相关 | 成功 |
| 这次采买尽量少花钱 | 两份水果清单（reason=recent） | **水果偏好未命中**；别名没有覆盖“采买/少花钱” | 由 recent 回退选中，而不是语义命中 | 部分失败 |
| 安排三次杠铃复合动作 | 健身偏好 | 无 | 无 | 成功 |
| 找几本感情线写得好的小说 | 水果采购清单（reason=matched） | **阅读偏好未命中** | 水果清单因通用词“适合”/最近回退被选中 | 明确失败 |
| 8 人户外野餐采购 | 水果偏好、两份水果清单 | 无 | 无 | 成功 |

## 4. 具体问题

1. **别名只能覆盖预料到的改写。**  
   “少花钱/采买”没有出现在水果别名中，仍然漏召回。维护者很难穷举未来措辞。

2. **Recent 回退会制造“看起来命中”的假象。**  
   没有匹配时，系统会补最近项目 note；在阅读任务中因此选中了水果清单。它不是语义匹配，可能造成误召回。

3. **通用词仍会造成词面误匹配。**  
   “适合”等泛词可能让无关 note 进入 `matched`。可以扩充停用词，但不能解决语义问题。

4. **未维护别名的高价值偏好会继续漏。**  
   阅读偏好没有别名，纯改写“感情线好的小说”没有召回。

5. **维护成本非线性增长。**  
   3 条 note 还很轻，但要覆盖所有 note/领域，需要持续预测措辞、处理误召回，成本会上升。

## 5. 是否值得继续投入

**值得继续，但只限小范围高价值 note。**

建议：

- 继续维护水果偏好、健身偏好等高频 note 的别名；
- 每次只补真实出现过的改写，不预先堆大量标签；
- 阅读偏好暂不扩张，除非它变得高频；
- 暂不引入 embedding：3 条 note 的别名已能覆盖已知场景，成本低于引入模型/依赖；
- 在继续前建议处理两个低层问题：
  1. recent 回退是否应默认启用，或只在用户显式允许时使用；
  2. 扩充通用停用词，并记录误召回。

### 何时重新评估 embedding

满足以下条件再考虑：

- 高价值 note 已有别名，但真实任务中仍然频繁漏召回；
- 漏召回造成的用户手动补充成本明显高于模型/依赖成本；
- 误召回无法通过标签收窄或停用词控制。

## 6. 完成判断

当前已经知道的具体问题是：

- 别名覆盖不足的未知改写；
- recent 回退带来的误召回；
- 通用词噪声；
- 未维护笔记的纯语义漏召回；
- 人工维护的扩展成本。

当前判断：**值得继续做小范围别名维护，但不值得全面重构或立刻上 embedding。** 下一步应先把 recent 回退和通用词噪声处理清楚，再决定是否扩大别名覆盖。
